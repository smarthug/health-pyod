# WESAD PyOD Dashboard — 발표 가이드 (비전공자용)

이 문서는 코딩/통계를 모르는 발표자도 대시보드를 자신 있게 소개하고 시연할 수 있도록 돕는 안내서입니다. 기술 용어를 최대한 줄이고, 한 줄 설명/대본/시연 순서 중심으로 구성했습니다.

---

## 1) 한 줄 요약
- 손목 밴드(센서) 데이터에서 “평소와 다른 이상한 순간”을 자동으로 찾아주는 대시보드입니다.
- 스트레스가 있는 구간을 잘 찾아냈는지, 간단한 지표로 확인할 수 있습니다.

---

## 2) 배경과 목적
- 데이터: WESAD라는 공개 실험 데이터(심박, 피부전도, 체온, 가속도 등).
- 목적: 일상 신호 속에서 “보통과 다른” 순간(이상)을 자동 탐지해, 스트레스 구간 같은 이벤트를 쉽게 확인.
- 가치: 의료·웰빙 서비스에서 이상 신호를 빠르게 파악하고, 후속 조치를 돕습니다.

---

## 3) 시스템 구성(아주 간단히)
- 프런트엔드: 웹 화면(React + MUI). 사용자는 여기서 실행 버튼만 누르면 됩니다.
- 백엔드: FastAPI + PyOD(이상 탐지 라이브러리). 복잡한 계산은 여기서 자동으로 수행됩니다.

필요한 이해: “실행 → 결과 차트와 숫자 지표 확인” 정도면 충분합니다.

---

## 4) 데모 준비 체크리스트
- 백엔드 실행
  - 터미널에서 `cd backend`
  - `uv sync` (최초 1회) → `uv run uvicorn api:app --host 127.0.0.1 --port 8001 --reload`
  - 브라우저에서 `http://localhost:8001` 열어 “WESAD PyOD API”가 보이면 정상
- 프런트엔드 실행
  - 새 터미널에서 `cd frontend`
  - `npm install` (최초 1회) → `npm run dev`
  - 브라우저에서 `http://localhost:5173` 접속
- 데이터 확인: `backend/data/WESAD` 폴더에 `S2`, `S3` 같은 피험자 폴더가 있고, 그 안에 `S*_E4_Data`가 있어야 합니다.

문제시 빠른 점검: 프런트에서 피험자/알고리즘 목록이 비면 백엔드가 꺼져있을 가능성이 큼.

---

## 5) 화면 구성과 용어(쉬운 말)
- Subject(피험자): 어떤 사람의 기록을 볼지 선택
- Algorithm(알고리즘): 이상을 찾는 방식(3가지 제공: ECOD, Isolation Forest, KNN)
- Parameters(파라미터): 기본값이면 충분. 필요하면 조절(아래 7장에서 설명)
- Run 버튼: 계산 시작. 몇 초 내 결과 표시
- Metrics(지표): 간단한 성능 숫자(AUROC, AUPRC, F1). 높을수록 대체로 좋음
- Charts(차트): 시간에 따른 점수, 이상으로 판단된 지점 등을 시각적으로 표시
- Interpretation(해석): 그래프 읽는 법과 이번 실행 요약을 문장으로 안내

---

## 6) 시연 대본(그대로 읽어도 됩니다)
1) “이 도구는 손목 밴드 센서 데이터에서 평소와 다른 구간을 자동으로 찾아줍니다.”
2) “왼쪽에서 피험자와 알고리즘을 고르고, Run을 누르면 됩니다. 기본 설정이면 충분합니다.”
3) “오른쪽에 결과가 나오는데, 위쪽 카드가 성능 지표, 아래가 그래프입니다.”
4) “빨간색은 ‘이상으로 판단된 순간’입니다. 파란색은 일반적인 구간입니다.”
5) “아래 해석 패널이 그래프를 어떻게 읽으면 되는지 쉽게 설명합니다.”

알고리즘 별 한 마디 설명:
- ECOD: “분포에서 튀는 값 찾기 — 단순하고 빠름”
- Isolation Forest: “쉽게 고립되는 점을 이상으로 간주”
- KNN: “주변과 멀리 떨어진 점을 이상으로 간주”

---

## 7) 파라미터를 쉽게 설명하는 법
- Contamination(오염도): “이상 비율 예상치”(0.05면 약 5%). 너무 크면 과도 탐지, 너무 작으면 놓침.
- Window/Step(윈도우/스텝): “몇 초 단위로 나눠 볼지” (기본 60초 윈도우, 30초 스텝).
- PCA Components: “요약 차원 개수” (기본 10, 모르겠으면 그대로).
- n_estimators(Iforest), n_neighbors(KNN): “알고리즘 설정값” (기본값 권장).

메시지: “모르면 기본값으로 두고 실행하세요.”

---

## 8) 차트 읽는 법(요점만)
- 공통: 점수가 높을수록 ‘평소와 다름’이 커짐 → 이상 가능성↑
- Threshold(임계선): 선을 넘으면 ‘이상’으로 표시

ECOD
- 메인: 파란 선(점수) + 빨간 점선(임계값) + 하단 슬라이더로 구간 확대
- 히스토그램: 오른쪽 꼬리가 길면 ‘높은 점수 구간’이 존재 → 이상이 있을 수 있음

Isolation Forest
- 파란 선(순간 점수) + 초록 면(평균 흐름) + 빨간 막대(이상 예측)
- 빨간 막대가 연속되면 의미 있는 이벤트 가능성↑

KNN
- 산점도: 파란 점(정상), 빨간 점(이상). 군집에서 멀리 떨어진 빨간 점은 강한 이상 신호
- 아래 미니 타임라인의 Brush로 구간 선택 → 위 산점도 자동 확대, Reset View로 원복

Interpretation(해석 패널)
- “원리”, “그래프 읽는 법”, “이번 실행 요약”, “상위 이상 구간”을 문장으로 안내 → 그대로 읽어주면 됨

Metrics(지표)
- AUROC/AUPRC/F1: “높을수록 대체로 좋음”. 절대값보다 ‘실험 간 비교’에 적합

---

## 9) 시연 순서(추천)
1) 피험자 S2 선택 → ECOD 실행 → 라인/히스토그램 소개(임계선과 꼬리)
2) IForest 실행 → 롤링 평균과 빨간 막대 포인트
3) KNN 실행 → Brush로 구간 확대 시연 → Reset View
4) Interpretation 패널에서 Top 5 이상 시간대 읽어주기
5) Metrics 카드에서 숫자 간단 비교(“이번엔 AUROC가 더 높네요” 정도)

---

## 10) 자주 받는 질문(FAQ)
- Q. ‘이상’이 꼭 ‘스트레스’인가요?
  - A. 아닙니다. ‘평소와 다름’을 찾는 도구이므로, 운동/센서노이즈도 이상으로 잡힐 수 있습니다.
- Q. 숫자가 낮으면 안 좋은 건가요?
  - A. 한 번의 숫자보다 여러 시도에서 상승/하락 추세를 보는 게 좋습니다.
- Q. 값(파라미터)을 어떻게 정하나요?
  - A. 기본값으로 시작하고, 필요시 Contamination만 조절해 감도를 맞춥니다.
- Q. 왜 결과가 사람/실험마다 다르죠?
  - A. 개인 차이와 상황 차이가 큽니다. 데이터 기반 현상으로 자연스러운 결과입니다.

---

## 11) 장애 대응(현장용 체크)
- 피험자 목록이 비어있다 → 백엔드가 꺼져있을 확률 큼. 8001 포트 확인.
- Run 눌러도 반응 없음 → 브라우저 개발자도구 Console/Network에서 에러 확인, 서버 로그 확인.
- 차트가 비어있다 → 데이터가 없거나 모두 필터링됐을 수 있음. 다른 피험자/파라미터로 재시도.
